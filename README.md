# Docautomate

Програма за офиса на Staff Consulting BG: данните за кандидат, работодател и длъжност се въвеждат **веднъж**, а програмата попълва всички бланки за случая и прави PDF.

Работи на един компютър, в браузъра. Данните остават на компютъра (папка `data`).

## Стартиране (Windows)

1. Еднократно: инсталирайте **Python 3.11+** от [python.org](https://www.python.org/downloads/) (отметнете „Add python.exe to PATH“) и **LibreOffice** от [libreoffice.org](https://www.libreoffice.org/download/) (за PDF). Ако на компютъра има Microsoft Word, PDF може да се прави и с него.
2. Пуснете **`start.bat`** (двоен клик). Първия път инсталира нужното (няколко минути), после отваря браузъра на `http://127.0.0.1:5000`.
3. Спиране: затворете черния прозорец.

Linux / macOS: `./start.sh`.

## Как се работи

1. **Работодатели** → нов работодател: фирма, ЕИК, адрес, представляващ (с пол, за „в качеството му/ѝ“).
2. При работодателя → **длъжност**: НКПД, място на работа, текстът на обосновката и длъжностната характеристика (пише се веднъж, ползва се за всички кандидати).
3. **Кандидати** → нов кандидат. Качете скан на паспорта и натиснете **„Разчети скана“**: програмата чете двата реда с `<<<` и попълва имената на латиница, паспорт №, пол, дати и гражданство. Проверете и поправете, после **Запиши**. Датата на издаване на паспорта и имената на кирилица се въвеждат ръчно.
4. **Случаи** → нов случай: кандидат + работодател + длъжност + вид случай + условия по договора.
5. В случая натиснете **„Генерирай PDF“**. Всяко генериране се пази в историята с дата. Старите PDF не се изтриват.
6. За подобен случай (друг кандидат при същия работодател, или удължаване) натиснете **„Копирай като нов“**.

Празно поле излиза в документа като „……………………“, за попълване на ръка. Страницата на случая показва кои полета са празни за всяка бланка.

## Бланки

- Основните 6 бланки (Заявление Прил. 3а, Контролен лист, Трудов договор BG/RU, Декларация за условия на труд, Обосновка, Длъжностна характеристика) идват с програмата, вече с полета.
- **Бланки** → отметки кои бланки се генерират за всеки вид случай.
- Нова бланка: Word `.docx` с полета като `{{ candidate.name_cyr }}`. Списъкът с полетата е в **Бланки → Списък на полетата**. При качване програмата проверява всяко поле и отказва бланка с грешно или непознато поле.
- Полета според пола: `{{ candidate.roden }}` (роден/родена), `{{ candidate.grazhdanin }}`, `{{ candidate.title }}` (г-н/г-жа), на руски `{{ candidate.ru_rodilsya }}` и др.

## Импорт от Airtable (еднократно)

- **CSV:** в Airtable → Candidates → Download CSV, после в програмата **Импорт** → изберете файла.
- **Директно:** в командния ред в папката на програмата:
  ```
  set AIRTABLE_TOKEN=pat...
  import-airtable.bat
  ```
  Токенът се задава само за прозореца и не се записва никъде.

Импортът може да се пусне отново без дублиране. Попълва само празни полета, така че поправките в програмата не се губят. Създават се кандидати, работодатели (само имена), длъжности (само имена) и случаи. ЕИК, адреси и останалите данни за работодателите се попълват в програмата.

## Пример с измислени данни

```
.venv\Scripts\python scripts\make_demo.py
```
Създава папка `demo-data` с един измислен случай и генерира всички PDF.

## За разработчици

```
python -m pip install -r requirements-dev.txt -r requirements-ocr.txt
python -m pytest
```

- `docautomate/app.py` уеб страници, `context.py` данните за бланките (списъкът `PLACEHOLDERS` е единственият източник), `render.py` проверка/попълване/PDF, `mrz.py` паспорт, `importer.py` Airtable.
- База: SQLite в `data/docautomate.db`. Папката `data/` не се качва в git (лични данни).
- Реални попълнени документи **не се качват** в репото. Бланките в `masters/` са без лични данни (има тест за това).
